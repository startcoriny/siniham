# 코딩 규칙

## 기본 원칙

- 요청받은 범위만 구현합니다. 추측성 기능은 추가하지 않습니다.
- 실제 요구사항과 현재 시스템에 필요한 범위까지만 구현합니다.
- 기존 코드베이스의 구조와 코딩 스타일을 우선 따릅니다.
- 기존 패턴이 있다면 새로운 패턴을 만들기보다 기존 패턴을 따릅니다.
- 요청 없이 불필요한 리팩터링을 수행하지 않습니다.
- 프로젝트에서 사용하는 코드 품질 기준과 정적 검사 규칙을 준수합니다.
- 과도한 추상화보다 이해하기 쉽고 유지보수하기 쉬운 구현을 우선합니다.

## 파일 헤더 규칙

새로운 소스 파일의 첫 줄에 파일의 역할을 설명하는 한 줄짜리 한국어 주석을 작성합니다. (CLAUDE.md 6번 규칙)

- 필수 지시문(`'use client'`, `'use server'`, shebang) 바로 아래에 배치합니다.
- 설정 파일(`*.config.*`, `package.json` 등)은 제외합니다.
- 파일명만으로 역할이 충분히 드러나는 경우에도 유지합니다. 다음 세션의 탐색 비용을 줄이는 것이 목적입니다.

예시.

```typescript
// 사용자 인증 상태를 관리하는 Context Provider
```

```python
# KIS API 호출을 비동기로 래핑하는 클라이언트
```

```sql
-- 일별 집계 결과를 저장하는 머티리얼라이즈드 뷰
```

## 주석 규칙

주석은 코드를 반복 설명하는 용도가 아니라 코드의 역할과 의도를 빠르게 이해할 수 있도록 작성합니다.

### 함수 주석

공개 메서드와 핵심 비공개 메서드에는 메서드의 역할을 한 줄로 요약하는 주석을 작성합니다.

예시.

- 단일 고객 조회
- 예약 생성
- 사용자 권한 검증

### 복잡한 로직

조건 분기, 알고리즘, 외부 시스템 연동 등 이해하기 어려운 로직에는 구현 이유(WHY)와 동작 방식(WHAT)을 함께 설명합니다.

### API 주석

API Endpoint를 제공하는 메서드에는 호출 경로(Method + Path)를 함께 작성합니다.

예시.

```text
GET /customers/{id}
POST /reservations
PUT /users/{id}
```
