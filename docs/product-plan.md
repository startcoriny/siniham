# 햄스터 육성 게임 — 확정 기획 문서

> 서비스명은 아직 미정 (원안 후보: 햄찌하우스 / 해미홈 / 햄스터 가든). 이 문서는 지금까지 논의를 통해 확정된 내용만 정리한 것으로, 실제 구현 시 이 문서를 기준으로 작업하면 된다.

---

## 1. 서비스 방향

> 여러 마리의 귀여운 햄스터를 돌보고 케이지를 꾸미며, 햄스터들의 다양한 행동을 관찰하는 웹 기반 힐링 육성 게임

이 한 문장과 직접 연결되지 않는 기능은 전부 후순위로 미룬다.

### 개발 조건
- 목적: 실제 사용자에게 공개할 정식 서비스
- 개발 인원: 1인 개발
- 비주얼 컨셉: 픽셀 아트 (기본 몸체 공유 + 색상/무늬만 변경하는 방식)
- 초기 사용자 규모: 지인 테스트 10~30명

---

## 2. MVP 범위

### 포함
- 햄스터 1마리 (여러 마리 육성은 2차 버전)
- 이름 설정, 케이지 화면, 배고픔/목마름/청결/기분 상태
- 먹이 주기, 물 주기, 쓰다듬기, 세수하기
- 쳇바퀴, 집, 잠자기
- 정원(식물 재배 + 잡초 제거) — 오프라인 진행 로직에 포함되므로 MVP 스코프에 포함
- 미션 시스템
- 가구 배치
- 회원가입/로그인 기반 서버 저장

### 제외 (후순위)
- 여러 마리 동시 육성
- 친구 방문/커뮤니티
- 교배 시스템
- 유료 결제
- 계절 이벤트, 사용자 간 거래

### 플랫폼
- PC + 모바일 반응형 웹 (반응형 레이아웃, 마우스/터치 입력 모두 고려)

## 3. 백엔드

### 스택
- **Node.js + TypeScript (Express)**
  - 프론트엔드도 TS라 타입 공유 용이
  - 케이지 로직이 정적 상태 표시 위주라 무거운 게임 엔진 불필요
- **Prisma** (ORM, 스키마/마이그레이션 관리)
- **PostgreSQL** — Docker 컨테이너로 앱과 같은 서버에서 직접 관리 (Neon 등 외부 관리형 서비스 안 씀 → 정책 변경 리스크 제거, 200GB 저장공간 활용)

### 인증
- **JWT를 httpOnly 쿠키에 담아 사용**
  - 별도 세션 저장소(Redis 등) 불필요
  - `localStorage` 대비 XSS에 안전
  - 프론트/백엔드를 같은 도메인에서 서빙하므로 CORS·쿠키 설정 단순

### 오프라인 진행 로직 (lazy-tick)
- 서버가 상시로 상태를 갱신하지 않고, 요청이 들어올 때 마지막 접속 시간(`lastActiveAt`) 대비 경과 시간을 계산해 일괄 반영
- 대상: 배고픔/목마름/청결 감소, 수면 상태 전환, 식물 성장, 잡초 생성, 미션 갱신
- **최대 계산 상한 3일** — 그 이상 방치돼도 배고픔이 무한정 깎이지 않도록 캡을 둠 (햄스터가 죽지 않는다는 원칙과 연결)
- 감소율(초안): 배고픔 8시간에 0, 목마름 6시간에 0, 청결 24시간에 0
- 30분 이상 상호작용 없으면 수면 상태로 전환

### 데이터 모델 (schema.prisma 기준)
User → Hamster / CageItem / GardenPlot / Mission / BehaviorLog (1:N)
CageItem → ItemMaster 참조

| 모델 | 주요 필드 |
|---|---|
| User | email, passwordHash, currency, lastActiveAt |
| Hamster | name, personality, appearance, hunger/thirst/cleanliness/mood/stamina/intimacy, growthStage, state |
| ItemMaster | name, type, cost, effectJson (정적 참조) |
| CageItem | itemMasterId, posX, posY |
| GardenPlot | plotIndex, plantType, growthStage, weedCount |
| Mission | missionType, progress, target, refreshedAt, completedAt |
| BehaviorLog | hamsterId, behaviorType, firstDiscoveredAt, captureImageUrl |

### API 엔드포인트 (초안)
- `POST /api/auth/signup`, `/login`, `/logout`
- `GET /api/me/hamster` — 오프라인 tick 계산 후 반환
- `POST /api/hamster/:id/feed` `/water` `/pet` `/clean`
- `POST /cage-items` (가구 배치)
- `POST /garden/:plotId/plant` `/harvest` `/remove-weed`
- `GET /missions`, `POST /missions/:id/claim`
- `GET /behavior-log`

## 4. 인프라/배포

- **서버: Oracle Cloud Always Free** (ARM VM, 2 OCPU / 12GB RAM, 200GB 스토리지 — 완전 무료, 기간 제한 없음)
  - 트레이드오프: 관리형 서비스가 아니라서 서버 세팅(Docker, Nginx, SSL, 보안 업데이트)을 직접 해야 함
  - 리전에 따라 무료 인스턴스 생성이 안 될 수 있음 (수요 초과 시 재시도 필요)
- **Docker Compose**로 app 컨테이너 + Postgres 컨테이너 관리 (DB는 외부 포트 노출 안 함)
- **Nginx** 리버스 프록시 (80/443만 외부 오픈)
- **Let's Encrypt**로 SSL 인증서 발급 (도메인 필요)
- **도메인: DuckDNS 무료 서브도메인** 사용, Oracle 예약 공인 IP에 연결
- 배포 방식: 초기엔 SSH 수동 배포, 이후 GitHub Actions로 자동화 예정
- **백업: 보류 항목** — Docker 자체 관리라 자동 백업이 없으므로 추후 cron + `pg_dump`로 일일 덤프 필요 (미착수)

## 5. 프론트엔드

- **React + TypeScript**, 스타일은 **Tailwind CSS**
- 케이지/캐릭터는 게임 엔진 없이 DOM(이미지 + CSS 트랜지션)으로 구현
- 구조: `Shell`(탑바 + 탭 콘텐츠 + 하단 탭바) → 각 탭 화면 컴포넌트

### 화면 구조 (6개)
1. 로그인/회원가입
2. 온보딩 — 색상 7종 중 선택 + 이름 입력
3. 메인 허브 (로그인 후 계속 유지, 탭으로 전환)
   - 케이지 탭 — 상태바, 액션 버튼, 꾸미기 모드 토글, 상세 정보 모달
   - 정원 탭 — 4구획, 탭하면 햄스터가 이동해서 동작(심기/제거/수확) 후 결과 반영
   - 상점 탭 — 아이템 그리드 + 구매
   - 도감·미션 탭 — 일일 미션 리스트 + 행동 도감 그리드

## 6. 햄스터 콘텐츠

### 외형 — MVP 기본 7종
골든, 그레이, 화이트, 베이지, 브라운, 차콜, 크림
(무늬/장모/특수 컬러 14종은 후순위 수집 콘텐츠로 이연)

### 성격
- 생성 시 랜덤 배정, 즉시 공개하지 않음
- 친밀도(intimacy) 30 이상이 되면 상세 정보에 노출 → 별도 시스템 없이 기존 친밀도 값 재활용

### 행동 정의 (11개, MVP)
| 행동 | 유저 조작 | 비고 |
|---|---|---|
| 걷기 | 아니오 | 자율 이동 |
| 서서 둘러보기 | 아니오 | 자율 |
| 먹기 | 예 | 배고픔 +30 |
| 물마시기 | 예 | 목마름 +30 |
| 잠자기 | 아니오 | 체력/기분 회복 |
| 쳇바퀴 타기 | 아니오 | 기분 +, 체력 - |
| 쓰다듬기 반응 | 예 | 친밀도 +5 |
| 세수하기 | 예 | 청결 +20. 모래목욕통이 있으면 자율로도 발생 |
| 볼에 저장 (희귀) | 아니오 | 해바라기씨 접시가 있을 때 자율 |
| 유저 쳐다보기 | 예 | 케이지 탭 시 |
| 정원 작업 (심기/뽑기/수확 공용 포즈) | 예 | 이동 후 동작 → 결과 반영 |

### 에셋 제작 전략
- 그려야 할 원화: **11개 포즈 × 기준색 1종 = 11장**
- 나머지 6개 색상은 색상 치환 스크립트로 자동 생성 (CSS 필터 대신 스크립트 방식 — 무채색 계열에서 결과가 부정확해지는 문제 회피)

### 가구
기본 지급. 먹이통, 물통(벽걸이), 집
상점. 물병(젖병형), 물그릇, 쳇바퀴, 모래목욕통, 해바라기씨 접시, 전망대
(화장실/쿠션 등은 세수·잠자기 기능과 중복이라 제외)

**터널 제외 (2026-08-02).** 원래 MVP 5종에 있었으나 "안으로 들어가 논다" 외에 붙일 행동이 없어
이미지도 로직도 없는 빈 아이템으로 남았다. 기존 행동표를 그대로 쓰는 가구 3종으로 교체했다.

| 가구 | 자율 행동 | 효과 |
|---|---|---|
| 쳇바퀴 | 쳇바퀴 타기 | 기분 +6, 체력 -8 |
| 집 | 잠자기 | 체력 +8 |
| 모래목욕통 | 세수하기 | 청결 +8 |
| 해바라기씨 접시 | 볼에 저장 | 기분 +6 |
| 전망대 | 서서 둘러보기 | 기분 +5 |

자율 행동 회복량은 사용자가 버튼으로 시키는 돌보기(+20~30)보다 작게 둬서 버튼을 대체하지 않게 한다.
연속 요청을 막기 위해 서버에서 20초 쿨다운을 적용한다.

## 7. 경제/미션 밸런스

- 신규 가입 스타터 재화: **100**
- 일일 미션 (자정 리셋, 하루 최대 55재화)

| 미션 | 조건 | 보상 |
|---|---|---|
| 밥 챙겨주기 | 먹이 3회 | 15 |
| 물 채우기 | 물 1회 | 10 |
| 애정 표현 | 쓰다듬기 3회 | 15 |
| 정원 돌보기 | 심기/제거/수확 중 1회 | 15 |

- 정원 수확: +5재화 (미션과 별개, 중복 가능)
- 잡초 제거: +1씨앗 (재화 대신)
- 상점 가격: 쳇바퀴 100 / 물그릇 30 / 젖병형 물병 50 / 모래목욕통·해바라기씨 접시·전망대 각 120
  (먹이통·벽걸이 물통·집은 스타터 기본 지급, 구매 불가)

## 8. 검증 계획

- 시기: 6개 화면 구현 완료 후 1~2주 테스트
- 배포: Oracle 서버 + DuckDNS 도메인으로 링크 공유
- 피드백 수집: 구글폼 3문항(재접속 의향/재밌었던 점/불편했던 점) + 디스코드 또는 오픈채팅
- 핵심 지표: 3일 이내 재접속률, 평균 세션 길이, 온보딩 완료율
- 통과 기준: 3일 재접속 40% 이상 + 온보딩 완료 90% 이상 → 여러 마리 시스템(2차 버전) 착수
