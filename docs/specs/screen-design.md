# 햄스터 육성 게임 - 화면 및 캐릭터 설계서

## 1. 설계 목적

이 문서는 햄스터 육성 게임의 프론트엔드 화면을 먼저 구현하기 위한 기준 문서다.

초기에는 실제 API를 연결하지 않고 목업 데이터를 사용해 다음 내용을 먼저 완성한다.

* 전체 화면 이동 구조
* 반응형 레이아웃
* 햄스터 캐릭터 표시
* 햄스터 상태 표현
* 사용자 액션 흐름
* 가구 및 정원 배치
* 상점과 미션 화면
* 로딩, 오류, 빈 상태

화면이 완성된 후 백엔드 API와 실제 데이터를 연결한다.

---

## 2. 전체 화면 구조

### 2.1 공개 화면

로그인하지 않은 사용자가 접근하는 화면이다.

1. 시작 화면
2. 로그인 화면
3. 회원가입 화면

### 2.2 초기 설정 화면

회원가입 후 처음 접속한 사용자가 햄스터를 생성하는 화면이다.

4. 햄스터 온보딩 화면

### 2.3 게임 화면

로그인과 온보딩을 완료한 사용자가 접근하는 영역이다.

5. 케이지 화면
6. 정원 화면
7. 상점 화면
8. 도감, 미션 화면
9. 설정 및 계정 화면

### 2.4 공통 모달 및 상태 화면

독립적인 페이지가 아니라 기존 화면 위에 표시한다.

* 햄스터 상세 정보
* 가구 상세 정보
* 가구 배치 모드
* 아이템 구매 확인
* 미션 보상 획득
* 행동 발견 알림
* 재화 부족 안내
* 로그아웃 확인
* 로딩 화면
* 오류 화면
* 네트워크 연결 끊김 안내

## 3. 전체 화면 이동 구조

```text
시작 화면
 - 로그인
     - 기존 사용자
         - 메인 게임

 - 회원가입
     - 햄스터 온보딩
         - 메인 게임

메인 게임
 - 케이지
 - 정원
 - 상점
 - 도감, 미션
 - 설정
```

로그인한 사용자가 이미 햄스터를 생성했다면 바로 케이지 화면으로 이동한다.

햄스터가 없는 사용자만 온보딩 화면으로 이동한다.

## 4. 공통 레이아웃

### 4.1 App Shell

로그인 이후의 모든 게임 화면은 하나의 공통 레이아웃 안에서 전환한다.

```text
상단 정보 영역 (프로필 / 재화 / 알림 / 설정)
현재 선택된 탭 콘텐츠
하단 탭 메뉴 (케이지 / 정원 / 상점 / 도감)
```

React Router를 사용해 페이지를 이동할 수 있지만, 게임 화면은 새로고침 없이 탭처럼 전환되는 느낌을 유지한다.

### 4.2 PC 레이아웃

PC에서는 좌측 메뉴와 중앙 게임 영역을 사용한다. 좌측(케이지/정원/상점/도감/설정) + 우측(상단 정보 영역 + 게임 콘텐츠) 2단 구조.

PC 기준

* 콘텐츠 최대 너비: 1200px
* 좌측 메뉴 너비: 180~220px
* 게임 영역은 가운데 정렬
* 케이지 화면은 최대 크기를 제한
* 화면이 넓어져도 햄스터가 지나치게 커지지 않게 한다.

### 4.3 모바일 레이아웃

모바일에서는 하단 고정 탭을 사용한다. 상단(프로필/재화) + 콘텐츠 + 하단 고정 탭(집/정원/상점/도감).

모바일 기준

* 하단 탭은 화면 아래에 고정
* 주요 액션 버튼은 엄지손가락으로 누르기 쉬운 위치에 배치
* 가구 배치는 터치 드래그를 지원
* 햄스터 클릭과 쓰다듬기 영역은 실제 이미지보다 넓게 설정
* 모달은 중앙 팝업보다 하단 시트 형태를 우선 사용

## 5. 공통 디자인 원칙

### 5.1 시각 스타일

* 픽셀 아트 기반
* 따뜻한 크림색 또는 연한 베이지 배경
* 진한 검정 대신 짙은 갈색 외곽선
* 둥글고 부드러운 UI 박스
* 과도하게 현대적인 유리 효과나 그라데이션은 사용하지 않음
* 버튼과 아이콘도 픽셀 스타일에 맞춤

### 5.2 권장 컬러

| 구분 | 역할 | 예시 |
| --- | --- | --- |
| 배경 | 전체 배경 | `#FFF4DD` |
| 카드 | 카드 및 모달 | `#FFF9EB` |
| 메인 브라운 | 테두리, 텍스트 | `#5A3928` |
| 포인트 핑크 | 코, 하트, 친밀도 | `#F28C9A` |
| 포인트 그린 | 정원, 완료 상태 | `#77A96B` |
| 포인트 옐로 | 재화, 보상 | `#F5C451` |
| 위험 표시 | 상태 부족 | `#D86464` |

색상은 초기 기준이며 실제 캐릭터 팔레트에 맞춰 조정한다.

### 5.3 UI 크기

* 모바일 최소 터치 영역: 44px 이상
* 버튼 높이: 44~52px
* 하단 탭 높이: 60~72px
* 본문 글자: 14~16px
* 주요 상태 숫자: 16~18px
* 화면 제목: 20~24px

## 6. 화면별 상세 설계

### 6.1 시작 화면

목적. 게임의 첫인상을 전달하고 로그인 또는 회원가입으로 유도한다.

주요 요소

* 서비스 로고
* 대표 햄스터 캐릭터
* 짧은 서비스 소개 문구
* 회원가입 버튼
* 로그인 버튼
* 서비스 이용약관 및 개인정보처리방침 링크

캐릭터 연출

* 햄스터가 화면 안을 천천히 걸어다님
* 일정 시간이 지나면 사용자 쪽을 바라봄
* 버튼 근처에 도착하면 잠시 앉아 있음
* 모바일에서는 성능을 위해 애니메이션 한 종류만 실행

제외. 초기 버전에서는 긴 서비스 설명, 영상 배경, 기능 소개 슬라이드는 넣지 않는다.

### 6.2 로그인 화면

목적. 기존 사용자가 계정에 접속한다.

구성 요소. 이메일 입력, 비밀번호 입력, 비밀번호 표시 토글, 로그인 버튼, 회원가입 이동, 로그인 오류 메시지

상태

* 기본. 입력 전 상태
* 입력 오류. 이메일 형식 오류 / 비밀번호 미입력 / 이메일 또는 비밀번호 불일치
* 처리 중. 로그인 버튼 비활성화 및 작은 햄스터 걷기 애니메이션 표시
* 로그인 성공. 햄스터 존재 여부에 따라 이동한다 (존재: 케이지 화면 / 없음: 온보딩 화면)

### 6.3 회원가입 화면

목적. 새 계정을 생성한다.

구성 요소. 이메일 입력, 비밀번호 입력, 비밀번호 확인, 이용약관 동의, 회원가입 버튼, 로그인 이동

유효성 기준. 올바른 이메일 형식, 비밀번호 최소 길이, 비밀번호 일치, 이메일 중복 여부, 필수 약관 동의

회원가입 성공. 회원가입 완료 후 바로 로그인 상태로 만들고 온보딩 화면으로 이동한다.

### 6.4 햄스터 온보딩 화면

목적. 사용자의 첫 햄스터 외형과 이름을 결정한다. 온보딩은 한 화면 안에서 2단계로 진행한다.

**1단계. 외형 선택**

선택 가능한 외형. 골든, 그레이, 화이트, 베이지, 브라운, 차콜, 크림

상호작용

* 색상을 선택하면 중앙 햄스터가 즉시 변경
* 선택된 햄스터는 서서 둘러보기 애니메이션 실행
* 사용자가 햄스터를 클릭하면 눈을 깜박임
* 기본 선택값은 골든

**2단계. 이름 설정**

이름 규칙. 1~10자, 공백만 입력 불가, 특수문자 범위 제한, 금지어 검사가 필요하면 추후 추가

생성 완료 연출

1. 햄스터가 눈을 감고 웃음
2. 작은 하트 이펙트 표시
3. "OO와 함께하게 되었어요" 메시지
4. 케이지 화면으로 이동

### 6.5 케이지 화면

목적. 게임의 핵심 화면이다. 사용자는 햄스터 상태를 확인하고 먹이, 물, 쓰다듬기, 세수하기 등의 행동을 수행한다.

전체 구조. 상단(이름/재화/설정) - 상태바(배고픔/목마름/청결/기분) - 케이지 스테이지(집/햄스터/물통/쳇바퀴/먹이통) - 액션 버튼(밥주기/물주기/쓰다듬기/세수하기) - 하단 탭(케이지/정원/상점/도감)

**상단 영역**

표시 정보. 햄스터 이름, 현재 재화, 친밀도 간단 표시, 설정 버튼, 알림 표시. 햄스터 이름을 누르면 상세 정보 모달을 연다.

**상태바**

MVP에서 화면에 바로 표시할 상태는 배고픔, 목마름, 청결, 기분 네 가지다. 체력과 친밀도는 상세 정보 모달에 표시한다.

상태 표현

| 값 | 표현 |
| --- | --- |
| 70~100 | 밝은 색상 |
| 30~69 | 일반 색상 |
| 1~29 | 경고 색상 및 아이콘 |
| 0 | 말풍선과 행동 변화 |

상태가 낮아지면 숫자만 줄어드는 것이 아니라 햄스터 행동에 반영한다.

예시. 배고픔 부족 -> 먹이통 근처로 이동 / 목마름 부족 -> 물통 근처에서 기다림 / 청결 부족 -> 불편한 표정 / 기분 부족 -> 활동량 감소

**케이지 스테이지**

햄스터와 가구가 표시되는 실제 놀이 공간이다.

권장 논리 크기. `1000 x 700`. 브라우저 크기에 따라 스테이지 전체를 비율에 맞춰 축소한다.

내부 좌표는 화면 픽셀이 아니라 비율로 관리한다.

```typescript
{
  posX: 0.35,
  posY: 0.72
}
```

이 방식은 PC와 모바일에서 같은 가구 배치 데이터를 사용할 수 있다.

레이어 순서

```text
1. 배경 벽
2. 바닥
3. 뒤쪽 가구
4. 햄스터
5. 앞쪽 가구
6. 행동 효과
7. 말풍선
8. 사용자 인터페이스
```

가구와 햄스터의 `posY` 값에 따라 앞뒤 순서를 조정한다.

**기본 가구 배치**

온보딩 완료 시 집, 먹이통, 물통을 기본 제공한다. 나머지 가구는 상점에서 구매한다.

초기 위치 예시. 집: 왼쪽 뒤 / 물통: 오른쪽 뒤 / 먹이통: 오른쪽 앞 / 햄스터 시작 위치: 중앙

**액션 버튼**

밥 주기. 밥 주기 버튼 선택 -> 먹이통 위에 강조 표시 -> 햄스터가 먹이통으로 이동 -> 먹기 애니메이션 실행 -> 배고픔 +30 -> 미션 진행도 반영

물 주기. 물 주기 선택 -> 햄스터가 물통으로 이동 -> 물 마시기 애니메이션 -> 목마름 +30 -> 미션 진행도 반영

쓰다듬기. 버튼을 누르거나 케이지의 햄스터를 직접 클릭 -> 쓰다듬기 애니메이션 -> 친밀도 +5 -> 다음 동작까지 약 1.2초 대기

세수하기. 햄스터가 앞발로 얼굴을 씻는 연출 -> 청결 수치 회복(+20) -> 완료 메시지

(원래 "케이지 전체 청소" 연출이었으나, 실제 스프라이트와 product-plan.md 행동표가 모두 세수하기라
2026-08-02에 세수하기로 통일했다. 케이지 전체 청소는 별도 에셋이 필요해 MVP에서 제외한다)

**햄스터 직접 클릭**

클릭하면 쓰다듬는다. 쓰다듬기 스프라이트(사람 손 포함)가 재생되고, 몸이 살짝 눌렸다 돌아오며 머리 위로
하트가 떠오른다. 친밀도 +5, 기분 +10, 애정 표현 미션 진행. 연달아 누르면 토스트가 쌓이므로 성공 안내는
하트 연출로 대신하고 오류만 토스트로 알린다.

(원래는 "쓰다듬기 모드를 켠 뒤 클릭", 그냥 클릭은 쳐다보기 등 가벼운 반응이었으나 2026-08-02에
클릭 = 쓰다듬기로 단순화했다. 상세 정보는 상단 "자세히 보기" 버튼으로 연다.
쳐다보기/말풍선/가까이 다가오기 같은 가벼운 반응은 아직 없다)

**꾸미기 모드**

진입. 화면의 "꾸미기" 버튼을 누른다.

꾸미기 모드 UI. 가구 외곽선 표시, 선택한 가구 이동, 배치 취소, 배치 저장, 가구 회수

배치 방식. PC(마우스 드래그, 클릭 후 위치 이동) / 모바일(길게 누른 후 드래그, 선택 후 빈 위치 탭)

배치 제한. 케이지 범위 밖 배치 불가, 기본 가구 겹침 제한, 햄스터 위 직접 배치 불가, 벽 전용과 바닥 전용 아이템 구분

MVP에서는 자유 회전 기능을 넣지 않는다.

### 6.6 햄스터 상세 정보 모달

목적. 메인 화면에 모두 표시하기 어려운 햄스터 정보를 확인한다.

표시 정보. 햄스터 이름, 외형, 성장 단계, 배고픔, 목마름, 청결, 기분, 체력, 친밀도, 성격, 생성일

성격 비공개 상태. 친밀도 30 미만이면 "성격: 아직 낯을 가리고 있어요. 친밀도 30이 되면 알 수 있어요."로 표시. 30 이상이면 실제 성격을 표시한다.

### 6.7 정원 화면

목적. 식물을 심고, 성장시키고, 잡초를 제거하며 재화와 씨앗을 획득한다.

화면 구조. 상단(정원/씨앗개수) - 4개 밭(2x2) - 햄스터 - 선택한 밭 정보(심기/잡초제거/수확 버튼)

**정원 구획**

총 4개 구획을 사용한다. 각 구획은 빈 밭, 씨앗 심음, 성장 중, 수확 가능, 잡초 있음 중 하나의 상태다.

밭 선택. 밭을 누르면 하단에 해당 구획의 정보가 표시된다.

* 빈 밭 - 심기 버튼 표시, 보유 씨앗 표시
* 성장 중 - 성장 진행 상태, 예상 남은 시간, 잡초 여부
* 수확 가능 - 수확 버튼 강조, 획득 가능한 재화 표시

**정원 작업 연출**

정원 작업은 즉시 숫자만 변경하지 않는다. 사용자 밭 선택 -> 햄스터가 해당 밭으로 이동 -> 정원 작업 애니메이션 -> 결과 반영 -> 보상 이펙트

심기. 햄스터가 땅을 파는 행동, 씨앗 감소, 성장 시작 시간 저장

잡초 제거. 햄스터가 잡초를 잡아당김(뒤로 넘어지는 연출은 후순위), 씨앗 +1

수확. 햄스터가 작물을 들고 기뻐함, 재화 +5, 밭을 빈 상태로 변경

**오프라인 진행 표시**

접속하지 않은 동안 식물이 성장했으면 정원 진입 시 요약한다 (예. "밤사이 정원에 변화가 있었어요. 당근 2개가 다 자랐어요. 1번 밭에 잡초가 생겼어요."). 오프라인 요약은 하루에 한 번만 표시한다.

### 6.8 상점 화면

목적. 재화를 사용해 놀이/돌보기 가구를 구매한다.

화면 구조. 상단(상점/재화) - 카테고리 탭(전체/가구/꾸미기, MVP는 실제 구현 불필요하나 컴포넌트 구조는 지원) - 아이템 카드 그리드

**아이템 카드**

픽셀 아이템 이미지, 아이템 이름, 가격, 보유 여부, 구매 버튼, 간단한 기능 설명

쳇바퀴. "햄스터가 신나게 달릴 수 있어요. 기분은 올라가지만 체력을 사용해요."

모래목욕통. "모래에 뒹굴며 스스로 몸을 씻어요. 청결이 조금씩 회복돼요."

해바라기씨 접시. "가끔 씨앗을 볼에 가득 채워요. 기분이 좋아져요."

전망대. "높은 곳에 올라가 케이지를 둘러봐요. 기분이 좋아져요."

(터널은 붙일 행동이 없어 2026-08-02에 위 3종으로 교체했다. product-plan.md 6장 참고)

**구매 흐름**

상품 선택 -> 상세 모달 -> 구매 확인 -> 재화 확인 -> 구매 완료 -> 가구 보관함 추가

재화 부족. "재화가 조금 부족해요. 미션이나 정원 활동으로 재화를 모아보세요."

MVP에서는 유료 재화 구매로 연결하지 않는다.

### 6.9 도감, 미션 화면

하나의 화면 안에서 상단 탭(일일 미션 / 행동 도감)으로 구분한다.

**일일 미션 탭**

표시 정보. 오늘 남은 미션 수, 자정까지 남은 시간, 미션 목록, 진행도, 보상, 보상받기 버튼

미션 카드 예시. "밥 챙겨주기 / 먹이 주기 2/3 / 보상 15 / [진행 중]" -> 완료 시 "먹이 주기 3/3 / [보상받기]" -> 수령 후 완료 도장 표시

**행동 도감 탭**

MVP 행동 목록. 걷기, 서서 둘러보기, 먹기, 물 마시기, 잠자기, 쳇바퀴 타기, 쓰다듬기 반응, 세수하기, 볼에 저장, 사용자 쳐다보기, 정원 작업 (11개)

미발견 행동. 실루엣 표시, 행동 이름은 `???`, 힌트는 일부만 제공 (예. "어떤 음식을 먹을 때 볼이 빵빵해질지도 몰라요.")

발견 행동. 행동 대표 이미지, 행동 이름, 최초 발견 날짜, 행동 설명, 해당 행동을 한 햄스터

**행동 발견 알림**

새 행동이 처음 발생하면 케이지 화면 위에 표시한다 (예. "새로운 행동 발견! 볼에 저장 / 도감에 새로운 기록이 추가되었어요."). 알림을 누르면 도감으로 이동한다.

### 6.10 설정 및 계정 화면

목적. 서비스 이용에 필요한 최소한의 계정 설정을 제공한다.

포함 기능. 이메일 확인, 햄스터 이름 변경, 효과음 켜기/끄기, 배경음 켜기/끄기, 애니메이션 효과 감소, 로그아웃, 회원 탈퇴, 이용약관, 개인정보처리방침, 버전 정보

MVP에서 비밀번호 변경 기능은 이메일 인증 방식이 없다면 후순위로 둔다.

## 7. 공통 상태 설계

### 7.1 로딩 상태

단순 스피너보다 햄스터 애니메이션을 사용한다 (예. 햄스터가 쳇바퀴를 타는 모습, 화면을 가로질러 걷는 모습, "햄스터 집을 정리하고 있어요."). 전체 화면 로딩은 최초 접속과 인증 확인 시에만 사용한다. 버튼 요청에는 작은 인라인 로딩을 사용한다.

### 7.2 빈 상태

* 도감이 비어 있는 경우. "아직 발견한 행동이 없어요. 햄스터를 천천히 관찰해보세요."
* 가구 보관함이 비어 있는 경우. "아직 배치할 가구가 없어요. 상점에서 새로운 가구를 만나보세요."
* 심을 씨앗이 없는 경우. "심을 수 있는 씨앗이 없어요. 잡초를 제거하면 씨앗을 얻을 수 있어요."

### 7.3 오류 상태

* 서버 오류. "햄스터 집에 잠시 문제가 생겼어요. 다시 시도해주세요."
* 네트워크 오류. "인터넷 연결이 불안정해요. 연결을 확인한 뒤 다시 시도해주세요."
* 요청 중복. 먹이 주기 등 액션 처리 중에는 같은 요청을 다시 보낼 수 없게 한다.

## 8. 캐릭터 설계

### 8.1 기본 캐릭터 규격

권장 스프라이트 크기. 기본 작업 크기 `48 x 48px`. 실제 화면에서는 정수 배율로 확대한다 (모바일 96x96px, PC 144x144px, 큰 미리보기 192x192px).

CSS에서는 `image-rendering: pixelated;`를 사용한다.

48px 크기는 눈, 코, 앞발, 볼, 무늬를 표현하면서도 픽셀 느낌을 유지하기 적절하다.

### 8.2 햄스터 비율

* 머리와 몸이 구분되지 않는 둥근 형태
* 전체 너비보다 높이가 조금 짧은 형태
* 귀는 작고 둥글게 표현
* 눈은 얼굴에 비해 작게 표현
* 코는 1~2픽셀 크기의 핑크색
* 앞발은 몸 앞쪽에 짧게 표시
* 발바닥과 귀 안쪽도 연한 핑크색 사용
* 입은 항상 표시하지 않고 행동에 따라 나타냄

얼굴 기준. 눈(검정 또는 짙은 갈색 1~2픽셀, 얼굴 중앙 기준 적당히 넓은 간격), 코(핑크색 1~2픽셀), 입(코 아래 1픽셀 또는 생략), 볼(먹을 때만 확장)

눈을 크게 만들지 않는 것이 현재 캐릭터 컨셉의 핵심이다.

### 8.3 픽셀 작업 규칙

* 안티앨리어싱 사용 금지
* 외곽선은 1~2픽셀
* 한 캐릭터에 4~7개 색상만 사용
* 명암 단계는 기본색, 밝은색, 어두운색 정도로 제한
* 반투명 픽셀 사용 최소화
* 눈과 코 위치는 모든 외형에서 동일하게 유지
* 색상과 무늬만 변경하고 신체 크기는 동일하게 유지

### 8.4 외형 7종

* 골든 - 주황빛 골드 털, 배와 입 주변은 크림색. 대표 기본 캐릭터
* 그레이 - 회색 털, 배와 얼굴 아래쪽은 흰색, 귀 안쪽은 탁한 핑크색
* 화이트 - 전체 흰색, 그림자 부분만 연한 회색, 코와 귀가 상대적으로 잘 보이도록 표현
* 베이지 - 연한 브라운 또는 샌드 컬러, 부드럽고 따뜻한 인상
* 브라운 - 진한 갈색 털, 배와 입 주변은 크림색
* 차콜 - 짙은 회색, 외곽선과 몸 색이 합쳐지지 않도록 하이라이트 추가, 눈 주변에 한 단계 밝은 색상 사용
* 크림 - 아주 연한 노란색, 화이트와 구분되도록 귀와 등 부분에 따뜻한 색조 사용

### 8.5 캐릭터 상태

| 상태 | 캐릭터 표현 |
| --- | --- |
| 기본 | 걷기, 둘러보기, 세수하기 |
| 배고픔 낮음 | 먹이통 주변 이동, 음식 말풍선 |
| 목마름 낮음 | 물통 주변 이동, 물방울 말풍선 |
| 청결 낮음 | 몸을 털거나 불편한 표정 |
| 기분 낮음 | 이동 빈도 감소, 앉아 있는 시간 증가 |
| 체력 낮음 | 집으로 이동 후 잠자기 |
| 기분 높음 | 빠르게 걷기, 짧은 점프 |
| 친밀도 높음 | 클릭 시 사용자 방향으로 이동 |

햄스터가 죽거나 사라지는 표현은 사용하지 않는다.

### 8.6 캐릭터 행동 상태 머신

상태. `IDLE`, `MOVE`, `USER_INTERACTION`, `FURNITURE_INTERACTION`, `GARDEN_WORK`, `SLEEP`

우선순위. 사용자 직접 행동 > 필수 상태 회복 행동 > 가구 상호작용 > 자율 행동

예를 들어 햄스터가 걷는 중 사용자가 밥 주기를 누르면 걷기를 중단하고 먹이통으로 이동한다. 잠자기 중에는 쓰다듬기 외의 행동을 제한할 수 있다.

### 8.7 MVP 애니메이션 목록

기획서의 11개 포즈는 정적인 화면 제작에는 충분하지만, 실제 애니메이션을 만들려면 각 행동마다 여러 프레임이 필요하다.

| 행동 | 권장 프레임 |
| --- | ---: |
| 기본 대기 | 4 |
| 걷기 | 6 |
| 서서 둘러보기 | 4 |
| 먹기 | 6 |
| 물 마시기 | 6 |
| 잠자기 | 4 |
| 쳇바퀴 타기 | 6 |
| 쓰다듬기 반응 | 4 |
| 세수하기 | 6 |
| 볼에 저장 | 4 |
| 사용자 쳐다보기 | 3 |
| 정원 작업 | 6 |

총 예상 프레임은 약 59프레임이다. 왼쪽/오른쪽 이미지를 각각 만들지 않고 CSS 좌우 반전(`transform: scaleX(-1);`)을 사용해 필요한 애셋 수를 줄인다.

### 8.8 스프라이트 시트 구조

행동별로 파일을 분리하거나 하나의 시트로 구성할 수 있다. 권장 방식은 행동별 분리다.

```text
hamster/
  base/
    idle.png, walk.png, look.png, eat.png, drink.png, sleep.png,
    wheel.png, pet.png, wash.png, cheek.png, garden.png
  generated/
    golden/, gray/, white/, beige/, brown/, charcoal/, cream/
```

행동별 파일로 분리하면 애셋 수정과 지연 로딩이 쉽다.

### 8.9 색상 치환 방식

기준 이미지는 골든 또는 무채색 마스크 버전 하나를 사용한다. 팔레트를 역할별로 구분한다.

```typescript
type HamsterPalette = {
  outline: string;
  furMain: string;
  furLight: string;
  furDark: string;
  belly: string;
  ear: string;
  nose: string;
};
```

색상 치환 시 눈과 코는 변경하지 않는다. 대상은 외곽선, 털 기본색, 털 밝은색, 털 어두운색, 배 색상, 귀 안쪽, 코. 각 색상을 고정 팔레트로 관리하면 모든 프레임에서 동일한 외형을 유지할 수 있다.

### 8.10 캐릭터 말풍선

햄스터가 직접 문장을 말하는 방식보다 작은 아이콘 말풍선을 사용한다.

예시. 배고픔(음식 아이콘), 목마름(물방울), 졸림(`Z`), 행복(하트), 궁금함(물음표), 불편함(작은 소용돌이), 새로운 물건 발견(느낌표). 말풍선은 2~3초 후 사라진다.

## 11. 화면 우선 개발 순서

1단계. 디자인 시스템 - 색상, 폰트, 버튼, 카드, 모달, 하단 시트, 상태바, 탭 메뉴, 토스트 알림

2단계. 인증과 온보딩 - 시작 화면, 로그인, 회원가입, 햄스터 선택, 이름 설정. 이 단계에서는 실제 API 없이 목업 처리한다.

3단계. 공통 게임 레이아웃 - 상단 정보 영역, PC 좌측 메뉴, 모바일 하단 탭, 페이지 전환, 반응형 처리

4단계. 케이지 정적 화면 - 배경, 기본 가구, 햄스터 표시, 상태바, 액션 버튼. 햄스터는 아직 움직이지 않아도 된다.

5단계. 캐릭터 애니메이션 - 대기, 걷기, 쳐다보기, 먹기, 물 마시기, 잠자기, 쓰다듬기

6단계. 케이지 상호작용 - 가구로 이동, 행동 실행, 상태 수치 변경, 가구 배치, 말풍선, 토스트

7단계. 정원 화면 - 4개 밭, 심기, 잡초 제거, 수확, 작업 애니메이션

8단계. 상점 화면 - 아이템 카드, 상세 모달, 구매 확인, 재화 부족 상태

9단계. 미션과 도감 - 미션 진행도, 보상 수령, 행동 도감, 발견 알림

10단계. 실제 API 연결 - 정적인 화면과 인터랙션이 완성된 후 다음 순서로 연결한다.

```text
인증 -> 사용자 정보 -> 햄스터 상태 -> 케이지 데이터 -> 햄스터 액션
-> 정원 -> 상점 -> 미션 -> 행동 도감
```

## 12. 화면 구현 완료 기준

화면 개발 단계는 다음 조건을 충족하면 완료로 본다.

* PC와 모바일에서 레이아웃이 깨지지 않는다.
* 모든 화면을 실제 버튼으로 이동할 수 있다.
* 모든 버튼에 기본, 활성, 비활성, 로딩 상태가 있다.
* 햄스터 외형 7종을 선택할 수 있다.
* 케이지에서 햄스터와 기본 가구가 표시된다.
* 먹이, 물, 쓰다듬기, 세수하기를 실행할 수 있다.
* 가구를 이동하고 저장할 수 있다.
* 정원 4개 구획의 상태를 표현할 수 있다.
* 상점 구매 성공과 실패 상태가 있다.
* 미션과 행동 도감의 잠금, 해제 상태가 있다.
* 로딩, 오류, 빈 상태가 준비되어 있다.
* 새로고침 전까지 프론트엔드 상태가 유지된다.

초기에는 상태 저장을 `localStorage`로 임시 구현하고, 화면 검증이 끝난 뒤 서버 저장으로 교체한다.
